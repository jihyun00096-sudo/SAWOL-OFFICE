# STEP 17 — 윤서진 비서실장

## 1. 목적

STEP 17부터 SAWOL OFFICE의 업무지시는 단순 입력 폼이 아니라
`대표 지시 → 비서실 분석 → 대표 확인 → 업무 등록` 흐름으로 동작한다.

중요한 원칙:

- 대표의 원문을 임의로 바꾸지 않는다.
- 분석 결과는 "제안"이다.
- 대표가 확인하기 전에는 실제 업무를 생성하지 않는다.
- 비용이 발생하는 외부 AI API는 아직 호출하지 않는다.
- 추천 근거와 신뢰도를 화면에 표시한다.
- 불확실할 때는 억지로 직원까지 자동배정하지 않는다.

---

## 2. 분석 항목

비서실장은 다음을 제안한다.

- 업무 유형
- 우선순위
- 추천 프로젝트
- 추천 부서
- 추천 담당 직원
- 대표 승인 필요 여부
- 작업 단계
- 분석 근거
- 분석 신뢰도

---

## 3. 현재 분석 방식

외부 LLM 대신 deterministic rule engine을 사용한다.

장점:
- 무료
- 결과 재현 가능
- API 장애 없음
- 민감한 회사 지시문이 외부로 전송되지 않음
- STEP 17 UI와 승인 흐름을 먼저 검증 가능

향후 실제 AI 모델을 연결할 때
`lib/sawol/secretary.ts` 부분만 서버 API로 교체하면 된다.

---

## 4. 업무 유형 분류

대표 입력의 제목 + 내용을 기준으로 분류한다.

예:
- 조사 / 찾아 / 비교 / 자료 → RESEARCH
- 기획 / 구성 / 전략 / 설계 → PLANNING
- 디자인 / 이미지 / 썸네일 / 상세페이지 → DESIGN
- 개발 / 코드 / 사이트 / 오류 / API → DEVELOPMENT
- 분석 / 검토 / 계산 → ANALYSIS
- 운영 / CS / 공지 / 관리 → OPERATION
- 수정 / 교체 / 보완 → EDIT
- 제작 / 작성 / 만들어 → PRODUCTION
- 학습 / 공부 / 정리 → STUDY

복합 업무일 경우 가장 강한 신호를 주 유형으로 선택하고
작업 단계에는 필요한 하위 과정을 함께 넣는다.

---

## 5. 우선순위

URGENT:
- 긴급
- 지금
- 즉시
- 오늘 안
- 바로 처리
- 장애
- 접속 불가

HIGH:
- 중요
- 우선
- 오늘
- 내일
- 마감

나머지는 기본 NORMAL.

대표는 제안 후 직접 변경 가능하다.

---

## 6. 대표 승인 필요

다음과 같은 최종 의사결정/위험 작업은 승인 필요로 제안한다.

- 삭제
- 결제 / 비용 / 예산
- 계약
- 외부 발송 / 공지 / 게시 / 배포
- 개인정보
- 법무
- 환불
- 고객 전체 대상 변경
- 프로덕션 배포

단순 조사/초안/내부 정리는 기본적으로 승인 불필요.

---

## 7. 프로젝트 추천

현재 존재하는 프로젝트명과 업무 문장의 단어 중첩도를 비교한다.

점수가 낮으면 억지로 프로젝트를 연결하지 않고
`프로젝트 연결 없음`을 제안한다.

대표가 드롭다운에서 직접 선택 가능하다.

---

## 8. 부서 추천

현재 DB에 실제 등록된 부서 이름과 업무 키워드를 비교한다.

예:
- 디자인 → 디자인 관련 부서
- 개발 → 개발/기술 관련 부서
- 콘텐츠 → 콘텐츠 관련 부서
- 마케팅 → 마케팅 관련 부서
- CS/고객 → CS/운영 관련 부서
- 재무/정산 → 재무 관련 부서
- 법률/계약 → 법무 관련 부서

적절한 부서를 찾지 못하면 미배정 상태로 둔다.

---

## 9. 직원 추천

현재 STEP에서는 직원의 전문역량 메타데이터를 별도 테이블에서
신뢰성 있게 읽지 않기 때문에 무리한 자동배정을 하지 않는다.

추천 부서가 정해졌더라도 담당 직원은
대표가 직접 선택할 수 있다.

향후 직원 스킬 매트릭스/성과 데이터가 연결되면 자동배정을 고도화한다.

---

## 10. DB 저장

대표가 승인하면 기존 `tasks` 테이블에 저장한다.

추가 분석 기록은 기존 JSON 컬럼에 보관한다.

input_data:
- source
- secretary_analysis
- confidence
- rationale
- suggested_steps

output_requirements:
- requested_result
- secretary_plan

DB 구조를 추가하지 않는다.

## 11. 테스트 케이스

### A. 리서치
제목:
서울 재개발 경쟁 강의 조사

내용:
비슷한 재개발 강의 10개를 찾아 가격과 커리큘럼을 비교해줘.

기대:
- RESEARCH
- NORMAL
- 승인 불필요
- 조사 단계 제안

### B. 개발
제목:
모바일 로그인 오류 수정

내용:
모바일에서 로그인 후 대시보드가 열리지 않는 문제를 찾아 수정해줘.

기대:
- DEVELOPMENT
- 오류 키워드에 따라 우선도 상승 가능
- 개발/기술 관련 부서 추천

### C. 위험 작업
제목:
기존 테스트 프로젝트 삭제

내용:
테스트 프로젝트를 모두 삭제해줘.

기대:
- 대표 승인 필요 = 예
