# SAWOL OFFICE — STEP 16 운영 관리 강화

## 목표

STEP 15가 "등록하고 보는 운영판"이었다면,

이번 단계 추가:

- 프로젝트 검색/필터

- 프로젝트 상태/진행률/현재 단계 관리
- 전체 업무 검색/필터
- 업무 상세 페이지
- 업무 내용 수정
- 업무 상태 변경
- 담당 부서 변경
- 담당 직원 배정
- 프로젝트 연결/해제
- 대표 승인 필요 여부 변경
- 결과함 검색/필터
- 결과 상세 페이지
- 결과 메타정보 확인
- 모바일 반응형 유지
- CANCELLED 등 위험 상태 변경 시 확인창
- 기존 RLS/대표 인증 유지

DB 스키마 변경 없음.

# 프로젝트 관리

`/projects`

검색:
- 프로젝트명
- 프로젝트 코드
- 현재 단계

필터:
- 상태
- 우선순위

`/projects/[id]`

수정 가능:
- 프로젝트명
- 최초 요청
- 목적
- 원하는 결과
- 상태
- 우선순위
- 위험도
- 현재 단계
- 진행률

진행률:
0~100 숫자만 허용.

CANCELLED 변경 시 브라우저 확인창 표시.

---

# 업무 관리

`/tasks`

검색:
- 제목
- 코드
- 설명
- 업무 유형

필터:
- 상태
- 우선순위

업무 카드 클릭:
`/tasks/[id]`

업무 상세 수정:
- 제목
- 설명
- 업무 유형
- 상태
- 우선순위
- 프로젝트
- 담당 부서
- 담당 직원
- 대표 승인 필요 여부

직원 배정 드롭다운은 활성 직원만 표시한다.

부서를 먼저 골라도 직원 목록은 전체 활성 직원이 표시된다.
부서별 자동 필터는 이후 UX 강화 단계에서 추가 가능하다.

---

# 결과 관리

`/results`

검색:
- 제목
- 결과 코드
- 요약

필터:
- 결과 유형
- 상태
- 최종본 여부

카드 클릭:
`/results/[id]`

결과 상세:
- 코드
- 제목
- 유형
- 상태
- 버전
- 최종 여부
- 담당 직원
- 생성일
- 요약
- DB에 존재하는 기타 필드 일부 확인

이번 STEP에서는 결과 자체를 수정하지 않는다.
AI 결과물은 추후 생성/검수 파이프라인과 함께 수정 정책을 붙이는 것이 안전하다.

# 안전 원칙

다음 상태 변경은 확인창 표시:

- 프로젝트 → CANCELLED
- 업무 → CANCELLED

대표가 직접 승인한 뒤에만 변경된다.

DELETE는 구현하지 않는다.

즉, 프로젝트/업무 데이터는 삭제가 아니라 상태 변경으로 관리한다.
