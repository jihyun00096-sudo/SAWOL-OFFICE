SAWOL OFFICE STEP32.0 — Discord 최종 상태 동기화

목표
웹에서 보이는 실제 업무 상태와 Discord 메시지를 최대한 같은 상태로 유지하고,
예전 상태의 메시지/버튼이 Discord에 남아 대표가 헷갈리지 않도록 정리합니다.

이번 수정
1. 진행 메시지 상태 동기화
- RUNNING → 승인 대기 이동 시 기존 업무-진행상황 메시지도 '실무 완료 · 대표 승인 대기'로 갱신
- PAUSED/FAILED 시 기존 진행 메시지도 같은 상태로 갱신
- COMPLETED 시 기존 진행 메시지를 '대표 승인 · 업무 완료'로 갱신

2. 승인 메시지 stale 버튼 제거
- 승인 완료 후 대표-승인대기 메시지의 승인/반려 버튼 제거
- 최종 결과 확인/업무 상세 버튼만 남김
- 웹에서 승인했더라도 autopilot notification sweep에서 동일하게 정리

3. 반려 상태 동기화
- 반려 시 기존 승인대기 메시지를 '대표 반려 · 재작업 시작'으로 변경
- 승인/반려 버튼 제거
- 업무-진행상황 메시지도 재작업 예정 상태로 정리
- 이후 RUNNING이 시작되면 같은 진행 메시지가 다시 실시간 업데이트

4. Discord /업무 접수 메시지 정리
- 원문 URL을 본문에 직접 표시하지 않음
- '업무 상세' 버튼으로 통일
- 링크 embed 억제
- 윤서진-비서실 / 업무-접수기록의 역할은 기존대로 유지

안전성
- SQL 없음
- 환경변수 없음
- npm 변경 없음
- DB 스키마 변경 없음
- AUTO 실행 엔진 변경 없음
- workflow 생성/배정 변경 없음
- 승인/반려 DB 로직 변경 없음
- Artifact Worker 변경 없음
- Live Office 변경 없음

변경 파일
- lib/discord/job-notifier.ts
- app/api/discord/interactions/route.ts

적용
1. ZIP을 현재 최신 프로젝트에 덮어쓰기
2. Commit / Push
3. Vercel Production Ready 확인
4. Discord 명령 재등록 필요 없음

간단 테스트
A. /업무 로 새 AUTO 업무 1개 접수
- 윤서진-비서실 / 업무-접수기록에 업무 상세 버튼 확인
- 본문에 긴 raw URL이 없는지 확인

B. 업무 진행
- 업무-진행상황 메시지가 새 메시지 도배 없이 같은 메시지로 갱신되는지 확인

C. 대표 승인
- 대표-승인대기 카드에서 승인
- 완료 후 예전 승인/반려 버튼이 사라지고 '대표 승인 · 업무 완료'로 바뀌는지 확인
- 업무-완료보고에는 최종 완료 메시지가 1개 존재하는지 확인

D. 대표 반려
- 승인대기 카드에서 반려 사유 입력
- 기존 승인 카드가 '대표 반려 · 재작업 시작'으로 변경되고 버튼이 제거되는지 확인
- 재작업이 시작되면 업무-진행상황 기존 메시지가 다시 업데이트되는지 확인
